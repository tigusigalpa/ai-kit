## Prepare and use the image

Build from the reviewed release checkout in PowerShell:

~~~powershell
$kitVersion = (Get-Content -LiteralPath .\VERSION -Raw).Trim()
docker build --build-arg "AIKIT_VERSION=$kitVersion" --tag "ai-kit:$kitVersion" --tag "tigusigalpa/ai-kit:$kitVersion" .
docker image inspect "tigusigalpa/ai-kit:$kitVersion" --format '{{.Id}} {{.Os}}/{{.Architecture}} {{index .Config.Labels "org.opencontainers.image.version"}}'
docker run --rm --init --network none --read-only --cap-drop ALL --security-opt no-new-privileges --tmpfs /tmp:rw,nosuid,nodev,size=256m "tigusigalpa/ai-kit:$kitVersion" memory --help
~~~

The prepared platform is `linux/amd64`; no multiarchitecture claim is made. The image includes the distribution, so host source mounting is unnecessary. Mount an application folder at `/workspace` for installation, or a chosen writable workspace for memory imports/merges/exports. The [Docker guide](../README.md#run-ai-kit-with-docker) explains preview/apply and host permissions. Raw private dialogue files belong in runtime storage and must not be added to the image.

## Docker Hub publication handoff

The intended repository is `tigusigalpa/ai-kit`, version tag `1.4.0`. Local preparation creates both `ai-kit:1.4.0` and `tigusigalpa/ai-kit:1.4.0`; it does not push either tag. Confirm the repository visibility and account permissions before an explicitly requested publication. [Docker's official instructions](https://docs.docker.com/docker-hub/repos/manage/hub-images/push/) describe tagging, pushing and checking the remote tag.

After publication is requested, use the reviewed local image:

~~~powershell
docker login
docker push tigusigalpa/ai-kit:1.4.0
docker buildx imagetools inspect tigusigalpa/ai-kit:1.4.0
~~~

Record the registry digest returned by the successful push and confirm the remote platform/version before distributing a digest-pinned pull command. A local image ID is not evidence of a Docker Hub upload. `latest` is not assigned automatically. Keep credentials out of scripts, reports and the build context; there is no push workflow or stored registry secret in this release.
