# AI-KIT v1.4.6

Review-driven release: identical LF bytes across Git, PyPI and Docker, an install-free project CI template, SIGTERM handling as PID 1, hash-pinned release builds with digest-verified uploads, selectable Docker cleanup, robust read-only project facts and doctor, and a landing-page README with user guides. [CHANGELOG](../CHANGELOG.md), [ADR 0016](adr/0016-consistent-distributions-and-safer-defaults.md).

Default installation behavior is unchanged: `docker_cleanup` defaults to `maximum`, presets and extras keep their meaning, and existing project files are preserved. Upgrading an installation made from a CRLF bundle records new source hashes without rewriting files.

## Verification

Verified locally on 2026-10-30 from clean `git archive` exports of the release branch (no CR bytes outside pinned vendor files):

- Docker Desktop client/server 29.9.2, context desktop-linux, dedicated `docker-container` builder. Image `ai-kit:1.4.6` (linux/amd64, UID/GID 10001:10001, entrypoint `aikit`) carries `org.opencontainers.image.licenses=MIT AND Apache-2.0`, version 1.4.6 and the source revision label. Smoke passed offline/read-only operation, refusal, all opt-in modules, preservation, stable reruns, the Docker ignore engine, LF-only packaged text, and SIGTERM both with `--init` and as PID 1 without it (exit 143, no forced kill).
- Packaged Linux/Python 3.13.16 discovery inside the image (non-root, offline, read-only root, temporary storage): 421 tests, all passed except three expected skips (two Windows-junction tests, one root-entry check for files the image does not ship). Linked-manifest and colon-path regressions ran on Linux.
- Wheel and sdist built from the export with hash-pinned tools passed metadata/resources/privacy/license checks; strict twine passed in a separate environment; offline fresh-venv wheel smoke passed. All 302 packaged files in the Windows-built wheel and the Linux image are byte-identical.
- Native Windows/Python 3.14.6 discovery and kit validation: see the [release summary](#release-summary).
- Test-run containers used `--rm`; the dedicated builder and its 619.6 MB cache and the superseded intermediate images were removed. Compared with the pre-task inventory, only the final local `ai-kit:1.4.6` image remains; no volumes, networks or containers were added. Host RAM/virtual-disk reclamation was not performed: it needs owner authorization and an idle window, and unrelated containers were running.

Not covered locally: hosted CI (runs on the pull request), the GitHub Release workflow, owner-approved PyPI upload, Docker Hub publication, macOS, other image architectures, Kubernetes server dry-run, and activation inside actual AI clients.
