# AI-KIT v1.4.6

Review-driven release: identical LF bytes across Git, PyPI and Docker, an install-free project CI template, SIGTERM handling as PID 1, hash-pinned release builds with digest-verified uploads, selectable Docker cleanup, robust read-only project facts and doctor, and a landing-page README with user guides. [CHANGELOG](../CHANGELOG.md), [ADR 0016](adr/0016-consistent-distributions-and-safer-defaults.md).

Default installation behavior is unchanged: `docker_cleanup` defaults to `maximum`, presets and extras keep their meaning, and existing project files are preserved. Upgrading an installation made from a CRLF bundle records new source hashes without rewriting files.

Smoke passed offline/read-only operation, refusal, all opt-in modules, preservation, stable reruns, the Docker ignore engine, LF-only packaged text, and SIGTERM both with `--init` and as PID 1 without it (exit 143, no forced kill).
- Packaged Linux/Python 3.13.16 discovery inside the image (non-root, offline, read-only root, temporary storage): 421 tests, all passed except three expected skips (two Windows-junction tests, one root-entry check for files the image does not ship). Linked-manifest and colon-path regressions ran on Linux.
- Wheel and sdist built from the export with hash-pinned tools passed metadata/resources/privacy/license checks; strict twine passed in a separate environment; offline fresh-venv wheel smoke passed. All 302 packaged files in the Windows-built wheel and the Linux image are byte-identical.
- Native Windows/Python 3.14.6 discovery: 421 tests, all passed with nine environment skips (symlink privilege, POSIX permission/FIFO checks, a colon file name that Windows forbids). Kit validation returned zero errors and zero warnings; Python 3.10 grammar holds for changed sources.
- Final local archives (local preparation hashes; hosted CI builds its own release artifacts): wheel `eb54b8322ba66dd277edd5bf8f69dfb6306a4da83d89d9c2b395e9d81d3bf479`, sdist `b79714c80e68c9a5992aab53b42cc4e699ee78cfd85c7d8893f995230eea7771`. - Test-run containers used `--rm`; both dedicated builders with their caches (619.6 MB and 341.2 MB) and the superseded intermediate images were removed. ## Release summary

Publication follows the [owner-approved PyPI path](PYPI.md#release-to-pypi-with-owner-approval): the GitHub Release prepares and verifies artifacts, then waits for the owner's approval before any upload. Docker Hub publication needs its own authorization and a build from the release tag.
