# AI-KIT v1.8.0

Independent control over AI-KIT model recommendations and instruction depth, with legacy defaults and truthful runtime reporting. [Usage](../README.md#keep-your-chosen-model-and-select-instruction-depth), [architecture audit](MODEL_INSTRUCTIONS.md), [changelog](../CHANGELOG.md).

## Changes and compatibility

- `model_switching_enabled` defaults to true when absent. False disables AI-KIT model/effort recommendations, cheap-model savings advice, adaptive model selection and model-selection proposals. Managed Codex helpers omit AI-KIT model/effort overrides; custom edits conflict. Existing Aider and user settings remain intact.
- Independent `instruction_profile` defaults to full. Minimal omits unsolicited optional workflows, roles and economic optimization, retaining mandatory project/nested rules, architectural decisions, security, owner conventions and critical quality/check requirements.
- Existing settings, clients, extras, private state and local changes follow the established upgrade/preservation rules. Installer presets and router optimization profiles do not reset the new controls.
- Preview, doctor, context and routing report effective controls. Parent model/effort remain unknown without actual platform evidence; configured pins and requested model names are not observations. No platform lock, parent effort change or hidden setting control is implemented.
- Explicitly enabled external execution remains separate, scoped and budgeted. Isolated benchmark projects inherit the controls; changing profiles cannot resume an incomparable experiment.
- Bounded Python setup retries improve repository CI/release resilience without replaying tests/uploads or bypassing owner approval.
