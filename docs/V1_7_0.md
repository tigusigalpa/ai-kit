## Behavior and compatibility

- Independent `--with-task-workflow` extra, off by default. Installation preserves existing clients/settings, creates a short managed contract and a project-owned example once, and launches no check or agent.
- Local `aikit task create|revise|status|transition|check|accept` commands implement explicit state changes, revision/reopening and preserved history. Mutations preview by default and require `--apply`.
- Every required check needs a current passing receipt bound to task definition/revision/cycle and Git HEAD/index/working-file fingerprint. Failed, interrupted, timed-out or source-changing checks cannot pass. Revisions and new cycles require fresh evidence.
- Acceptance needs the exact fingerprint plus explicit evidence for every criterion. This is a local reviewer assertion, not authenticated identity or automatic semantic proof. Changed accepted code is reported stale; historical approval stays visible.
- Task records stay private in ai-kit/.tasks/ in both sharing modes, survive upgrades and are excluded from source distributions, wheels and image context.
- Checks run with current local permissions/environment, without an implicit shell, but are not sandboxed. Ignored dependencies/services/tool versions and adversarial intermediate edit-and-restore are outside source evidence. Source checks require a Git working-tree root; linked paths, submodules, unresolved merges and known nonignored credentials are refused.
- Automatic coordination, agents/model execution, retry/review loops, hosted-CI import and Git/deployment actions remain separate. Existing instruction defaults and optional modules are unchanged.
