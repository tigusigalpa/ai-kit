# AI-KIT maintenance continuity

Read [current facts](../../../PROJECT_CONTEXT.md) and [maintainer instructions](../../../AGENTS.md).
Keep the root context/history about this kit; keep template project facts uninitialized.
For a procedure change, update current maintainer commands, this pointer contract, and relevant implementation docs in the same task.
When verified facts or agreements change, synchronize this skill's scope/procedure/pointers and WIKI with the context; keep actual facts in context.
Validate templates/links/registry, the agent registry (integrations/agents.json), and behavioral installation scenarios; record root CHANGELOG entries. Keep the root SKILL.md (the repository as a skill) consistent with the CLI, presets, extras, and policies.
Review explicit semantic acceptance and future-upgrade conflicts whenever installer baseline behavior changes.
Check candidate draft preservation, state/settings validation, and adapter retirement conflicts when changing installation. Exercise installed Git visibility and portable linked-path refusal; distinguish synthetic fixtures from real application trials.
Exercise file-versus-directory native rule layouts on both probe and selected-write paths: simulate POSIX ENOTDIR on Windows, preserve existing file markers and rerun stability, and refuse blocked selected parents before writes. Do not hide permission failures or linked-path refusals during optional adapter probes; see [file-parent compatibility](../../../docs/ADAPTER_PATH_FIX.md).
Exercise manifest-based profile detection and project-fact drafts (version/commands into PROJECT_CONTEXT and project.json), scoped Node/Python ignore rules, the installed-project doctor report, opt-in extras (session-start, guards, CI) including key-level client settings merges, legacy whole-file migration, and hook execution, client detection markers, interactive/check onboarding, the adr/changelog helpers, and the offline router helper (route/configure with provider selection) when installer behavior changes.
For generated client configuration, exercise private/team settings files and mode switches, owned-entry moves, project.json precedence, secret lists, ignore blocks, every scoped rule format with root modules and skipped paths, presets that turn extras off, and workflow skill copies; recheck client formats against primary docs before changing them.
For routing, compare the implementation ladder with canonical POLICY, exercise English/Russian operation/risk regressions and override precedence, provider-review status/sources, and distinguish recommendations from executed model controls. For stack profiles, exercise manifest evidence, module scoping, and command drafting; for Filament specifically test Composer dependency/lock evidence and source/native skill lifecycle. For optional metrics, verify failure/recovery accounting, missing-value coverage, duplicate/lock/path guards, private/team journal visibility, schema 1/2 compatibility, experiment/arm/task identity, per-provider analyze output, and upgrade preservation. Exercise context snapshots and doctor warnings for new/removed modules, profile drift, and manifest changes. Exercise adapter reports plus explicit retirement of unchanged files, backups/state updates, and modified-file conflicts. Exercise opaque evaluator pair coverage without task-text persistence. Use the [evaluation protocol](../../../docs/EVALUATION.md) for separately authorized application trials; synthetic fixtures establish no savings.
Record actual OS/runtime and unavailable checks in the implementation record; keep source visibility checks separate from client activation.
For measurement-led changes, test schema 1/2/3 compatibility, fixed A/B controls, immutable Git blobs and isolated repeated workspaces, missing/estimated telemetry, semantic-review gates, interrupted runs and idempotent private exports. Exercise resume identity checks, per-unit failure recording and configurable kit-arm agents/presets. Check that worker Git discovery cannot reach the source through parents: a ceiling at cwd itself is ineffective. Keep worker requests separate from observed execution. Exercise routing modes/pins/profiles, distinct-case quality floors, matched history, unsupported controls, immutable proposal history and explicit backed-up restore. Exercise module context scope, duplicate content, critical rules/ADRs above byte budgets and linked paths. Follow [the staged plan](../../../docs/DEVELOPMENT_PLAN.md) and [worker contract](../../../docs/BENCHMARK.md); defer live adapters/orchestration until their mechanisms and total coordination costs are verified.
Resolve temporary fixture roots before deriving paths used by guards, assertions, or injected failures. Test equivalent path spellings; keep cleanup bound to original disposable directories. [Windows CI regression](../../../docs/WINDOWS_CI_FIX.md) records the relevant scenario.
For reference upgrades, check the actual published tree and old paths left by overlays. Compatibility pointers link to canonical owners; never hide broken legacy links from the checker.
When editing onboarding docs, verify examples against the actual CLI/defaults and preserve links to policy owners. Keep installation, native discovery, and measured execution claims distinct. For [OpenRouter documentation](../../../README.md#working-with-openrouter), recheck primary API/cache/usage docs; distinguish shipped context manifests from proposed request assembly/runtime, prompt caching from response reuse, and observed usage from assumed savings. Root README has its own 32000-byte budget; do not expand project instruction budgets with it.
When packaging changes, build the wheel without runtime dependencies and smoke-install it in isolated Windows, macOS, and Linux environments. Keep MCP posture separate from client activation: verify documentation and capability records, never infer a live connection from a configuration file.
For repository administration or CI changes, consult [repository maintenance](../../../PROJECT_CONTEXT.md#repository-maintenance), verify live protection and emitted check names, and keep required checks aligned with the workflow. Record the revision and read-back evidence; remote changes need explicit authorization, and Core still governs commits/pushes.
For optional upstream skills, follow [security-audit](../../../docs/SECURITY_AUDIT.md) and [Strix integration](../../../docs/STRIX.md): preserve pinned bytes/license and newline attributes, verify bounded tree coverage/digests and nested-path aliases, explicit-only metadata, absent default/preset payloads, independent persistent choices, local adaptations/conflicts, links, visibility and wheel resources. Exempt only verified external examples from authored model/language/budget checks. Keep installation separate from audits/runtime setup; report unsupported validators. For Strix, check writable copy isolation, explicit full/diff scope, budget/data destination and no implicit cloud fallback; integration tests must start no scan, model or container.
For [Context7](../../../docs/CONTEXT7.md), check opt-in skill/registry selection, independent persistence, source/native copies, local conflicts and unchanged native MCP configuration. Keep normal skill discovery, version-aware sanitized queries and remote activation separate. Recheck client schemas/authentication against primary docs; a source revision does not pin the hosted service.
For an explicitly requested release version, update VERSION, the root changelog, README release pointer, WIKI and maintainer context together; keep release history out of project templates. Recheck CLI version, kit validation and wheel metadata/install; build in an isolated source copy and exercise preservation across the prior-version baseline. State which behavioral results preceded release labeling; publication/tagging remain separate actions under Core. In release notes, describe Context7 setup separately from installation and OpenRouter guidance separately from a live adapter; verify security capability examples against pinned contracts.
Do not bootstrap the reference repository as an application or imply native/runtime checks passed from static validation.
